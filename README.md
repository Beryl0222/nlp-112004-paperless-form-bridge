# 无纸申报表的双语填写与转送

澄港与弦港的电子单据联调使用两种收件样式，既有按键分栏的对象，也有固定列顺序的行。日期和时间使用 ISO 8601。表单说明按原样留档，收件样式文件记录合作方实际可接收的值域。

## 本地资料

全部为 UTF-8 编码的合成业务资料。`data/contract.json` 中的列类型带 `?` 时可以是 JSON null。每组记录的 `id` 在该组中唯一，跨组关系以字段说明和清单的 `links` 为准。文字字段保留来源原句，嵌套对象按表中现有格式记录。

- `data/forms.json`。合作方的收件样式与解释权限。fields 列出目标字段、顺序或对象键、可表示的空值及约束。authority 为 null 表示未指定。
- `data/instructions.json`。发行的原始条款段，clause 是印刷定位，supersedes 可指向前一段。
- `data/participants.json`。经合作方登记的申报参与人及业务身份。
- `data/drafts.json`。顺序为接件顺序。原回复句可能含交叉引用。kind 为自述、代答、书面确认或更正。
- `data/receipts.json`。联调中在合作方真正留档的申报件。payloadText 为原串，viewText 为交接时柜员看到的文字。

## 使用约定

收件值中的 OMIT 表示完全不存在这个键。JSON 对象禁止以 null 代替缺失键。CSV 以表中列次输出，空串与引号遵守常用 CSV 转义，不能加入收件方未登记的列。Y/N 只用于收件方的二选一属性，不代表其他栏位的空值。
业务中用到的窗口站点码为 E-07（东泠）和 Q-02（桥浦）。参与人登记角色与其在草稿中实际承担的角色可以不同。说明文本中编号相同的新版段落只替代旧段落，其他条款继续有效。可通过原件号标明对哪次交接提出更正。

## 读取与检查

使用 Node.js 22.23.4，依赖仅用 Node.js 标准库。资料检查依次读入各组 JSON，检查列类型、组内编号及已登记的组间引用，并列出各组记录数。读取入口为 `tools/materials.mjs`，可单独读取一组记录，或读取整个已登记资料包。

```sh
npm run check-data
npm test
```

## 填写与转送

`tools/cli.mjs` 是柜员用的填写与转送工具，默认读写 `data/` 与 `state/`（柜员本地确认记录，不入包）；可用环境变量 `PFB_DATA`、`PFB_STATE` 指向其他目录（如演练副本）。

```sh
node tools/cli.mjs terms   <表单> --edition <版次>      # 两种文本各自赋予栏位的义务、例外、补答人、触发条件
node tools/cli.mjs case    <案件> --edition <版次>      # 案件条件、栏位状态、冲突处理、追问与暂缓
node tools/cli.mjs confirm <案件> --edition <版次> --field <栏位> --group <组> --clauses <条款,逗号分隔>
node tools/cli.mjs preview <案件> --edition <版次>      # 以收件方实际读法预览草稿
node tools/cli.mjs issue   <案件> --edition <版次> [--corrects <原件号>]
node tools/cli.mjs receipts [--case <案件>]             # 回查已交接的申报件
node tools/cli.mjs verify  <申报件号>                   # 核对预览与申报件是否对应
```

处理约定：

- 说明条款按版次生效，编号相同的新段落只替代旧段落；脚注引用可把要求限定在特定身份、货物情况或申报方式。同一段说明覆盖多个栏位时分别归位，两种文本措辞或分栏不同但要求相同的视为一致。
- 义务冲突时按收件方标明的约束版本（forms 的 authority）处理；无约束版本、且解释仍会改变填法时，受影响栏位及依赖它的转送暂缓，不猜译法放行。空值含义的冲突只在真会留空时才暂缓，实值栏位不受影响。
- 柜员可依据原文确认一项解释（confirm）。确认记录说明版次与当时的案件条件，只在该版本与条件下适用；客户改口使条件变化后，原确认不再让旧填法有效，未受影响的确认与回答继续并存。
- 栏位状态区分：已回答、明确没有、未回答、无权填写、按条件无需填写、多义。代办方只能补答说明准许的栏位；不得代用的值（如以代办方代码冒充货主代码）被拒并注明依据。无法拆开的原答复保持联合，不臆造拆成几个独立值。
- 追问会写明由谁补什么。两种有效状态在收件格式中含义相同（如“明确没有”与“未回答”同为空串）时，预览说明丢失了什么、需要哪一方澄清，草稿保留供继续办理。
- 预览以收件方实际能读到的栏位与空值含义生成，每个值可回到原回答或书面说明。签发的预览必须与实际申报件对应，`verify` 可核对；早期留档不是本工具格式时如实报告。
- 申报件只增不改。已有交接记录的案件只许以关联原件的更正件（预览首行注明原件号）重办，原件保留可回查。
