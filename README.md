# 无纸申报表的双语填写与转送

澄港与弦港的电子单据联调使用两种收件样式，既有按键分栏的对象，也有固定列顺序的行。日期和时间使用 ISO 8601。表单说明按原样留档，收件样式文件记录合作方实际可接收的值域。

## 本地资料

全部为 UTF-8 编码的合成业务资料。`data/contract.json` 中的列类型带 `?` 时可以是 JSON null。每组记录的 `id` 在该组中唯一，跨组关系以字段说明和清单的 `links` 为准。文字字段保留来源原句，嵌套对象按表中现有格式记录。

- `data/forms.json`。合作方的收件样式与解释权限。fields 列出目标字段、顺序或对象键、可表示的空值及约束。authority 为 null 表示未指定。
- `data/instructions.json`。发行的原始条款段，clause 是印刷定位，supersedes 可指向前一段。
- `data/participants.json`。经合作方登记的申报参与人及业务身份。
- `data/drafts.json`。顺序为接件顺序。原回复句可能含交叉引用。kind 为自述、代答、书面确认或更正。
- `data/receipts.json`。联调中在合作方真正留档的申报件。payloadText 为原串，viewText 为交接时柜员看到的文字。

## 使用约定

收件值中的 OMIT 表示完全不存在这个键。JSON 对象禁止以 null 代替缺失键。CSV 以表中列次输出，空串与引号遵守常用 CSV 转义，不能加入收件方未登记的列。Y/N 只用于收件方的二选一属性，不代表其他栏位的空值。
业务中用到的窗口站点码为 E-07（东泠）和 Q-02（桥浦）。参与人登记角色与其在草稿中实际承担的角色可以不同。说明文本中编号相同的新版段落只替代旧段落，其他条款继续有效。可通过原件号标明对哪次交接提出更正。

## 读取与检查

使用 Node.js 22.23.4，依赖仅用 Node.js 标准库。资料检查依次读入各组 JSON，检查列类型、组内编号及已登记的组间引用，并列出各组记录数。读取入口为 `tools/materials.mjs`，可单独读取一组记录，或读取整个已登记资料包。

```sh
npm run check-data
npm test
```
